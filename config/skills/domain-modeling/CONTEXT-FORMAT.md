# Compact glossary format

Use the project's existing glossary and structure first.
If an authorized documentation change needs a new home, keep it small:

```markdown
# Domain terms

## Term

Meaning: the established business concept.
Identifier or representation: when needed to distinguish another concept.
Owner and relationships: facts relevant to using the term correctly.
Evidence: the source of this meaning.
```

Use familiar project terms, define consequential distinctions, and label unsettled meanings as proposals.
Do not invent a context map or multiple glossary files without a demonstrated ownership need.
Avoid duplicating implementation details that are inexpensive to inspect directly.
